# Ike Starter Set

The IkeFoundation knowledge set: an append-only version ledger whose releases are change
sets. Generated by `ike:starter-set-create`.

**Set identity (permanent):** `d890e06f-ec35-429a-b541-d0ead19695e2` — the type-5 namespace from which every
identity in the set derives. Never change it; never reuse a birth FQN.

## Prerequisites

- **JDK 25 or newer.** On 24 the build fails with `Required Java version 25 is not met by
  current version: 24.0.2` — a plugin prerequisite, so it fails two lines after the project's
  own enforcer has accepted 24.
- **Maven 4.**
- **The sibling repository providing `network.ike.knowledge:ike-knowledge-provider:1-SNAPSHOT`,
  built and installed first.** Until it is in the local repository `mvn install` cannot resolve
  it, and the reactor stops at `ike-terms`.

Chapters are declared in place and assembled at build time — see
[`ike-hierarchy-maven-plugin`](ike-hierarchy-maven-plugin/README.md) and its
[`docs/`](ike-hierarchy-maven-plugin/docs) ([add a chapter](ike-hierarchy-maven-plugin/docs/ADD_CHAPTER_TUTORIAL.md), [integrate downstream](ike-hierarchy-maven-plugin/docs/INTEGRATION_GUIDE.md)).

The standard operating procedure is the `dev-knowledge-set-sop` topic family in
`ike-lab-documents`. The short loop:

```bash
mvn install                       # ledger -> bindings, change set, glossary, KB
open ~/Solor/ike-kb            # select in Komet; verify; edits are captured
```

Captured verification change sets land in `~/Solor/ike-kb/changeSets/` and feed
the next iteration as `CHANGESET` inputs in `ike-kb/pom.xml`.
